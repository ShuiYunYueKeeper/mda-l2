Why MDA

Not another Markdown editor —
the part after the file arrives.

✎

Comments in the file

A standard Markdown comment carries the structured comment. GitHub, Typora and Obsidian render nothing; git diff shows everything. Change tools and nothing is lost.

◧

Preview is the editor

Click into rendered text and type. **, ~~ and backticks stay hidden; tables, code blocks and Mermaid are editable in place, and the file on disk stays clean source.

↗

Delivery without conversion

Single-file HTML / PDF / Word export and one-click rich text for WeChat. Local images, KaTeX formulas and diagrams are embedded — no network required.

⌘

Agents can take over

A built-in stdio MCP server exposes six tools: scan, add, edit and remove comments, read a file, export a review prompt. Works with Claude Desktop, Cursor and other clients.

Comments in the file

Feedback travels with the file,
not with a system.

A comment is not a database row or a sidecar file. It is a valid Markdown link reference definition placed above the paragraph it reviews. It is copied, committed and merged with the document; removing it never touches a body line.

  • Paragraph- and selection-level anchors, with two-way navigation
  • critical / major / minor / info severity, open / resolved / wontfix status
  • Source protection and atomic writes; CRLF / LF preserved
samples/demo.mdsource
[comment]: <> (@anno {"id":"…","content":"This conclusion needs supporting data","tags":["evidence"],"level":"major","status":"open"})

Features

Everything you need,
nothing that gets in the way.

Three-pane workbench

Independent edit and comment toggles around a permanent preview; all three panes can sit side by side, resizable and double-click to reset.

Selection comments

Select a sentence in preview or source, leave a comment on exactly that range; highlight and panel entry locate each other.

Tables and code in place

Edit table cells, fenced code and Mermaid source directly in the rendered layer, with the same inline-style rules as body text.

Mermaid · KaTeX · HTML blocks

Offline diagrams, typeset formulas, and README-style HTML badges or <details> rendered as cards.

Export and WeChat

Single-file HTML / PDF / Word; copying for WeChat embeds images, formulas and diagrams as PNG automatically.

File tree · outline · sessions

Drag, rename, copy/move (undoable) and delete with confirmation inside a workspace tree; outline follows the caret; last session and window layout are remembered.

Dark mode · Chinese and English UI

Follow the system or switch manually; syntax colors and diagrams follow the theme, and the UI language changes instantly.

Three entry points, one core

GUI, mda-cli and mda-mcp share @mda/core, so automation behaves exactly like the app.

Works offline

No login, no activation, no network. Every rendering asset ships with the installer.

Workflow

Four steps from inbox to hand-off.

  1. 01

    Open

    Drop in a .md or pick a workspace folder; the Markdown tree, outline and recent files are ready.

  2. 02

    Read and edit

    Change a few lines in the preview or switch to source. Saving is atomic and keeps the original line endings.

  3. 03

    Comment

    Comment on a paragraph or a selection with severity and tags. Mark it resolved and it still stays in the diff.

  4. 04

    Deliver

    Export Word / PDF, copy into WeChat, or let an MCP client pick up the comments and continue.

FAQ

Common questions

Do comments break Markdown compatibility?

No. A comment is a CommonMark link reference definition ([comment]: <> (@anno {…})) and produces no visible output. Tools that do not understand the payload see an ordinary reference line. Body text is never modified.

How is MDA different from Typora, Obsidian or VS Code?

Those are a writing tool, a knowledge base and a general editor. MDA covers the step after you receive a .md: understand it, change a few lines, leave structured feedback, export what the other side needs, then hand it to an agent. Comments living in the file and MCP being a first-class entry point are the practical differences.

Which platforms are supported?

Windows, macOS and Linux. Windows builds include an installer, a portable exe and a zip; macOS and Linux packages must be built on their own platform, and the electron-builder config ships in the repo.

Is it free, and are my documents uploaded?

Free and open source under MIT, with no account or activation. The app only reads and writes the files you open; preview, export and WeChat copy run locally. The MCP server is restricted to paths under --workspace.

How do I connect an agent?

Point your MCP client at dist/mcp/server.js, optionally with --workspace to limit accessible paths. Six tools: scan, add, edit and remove comments, read a file, and export a review prompt.
